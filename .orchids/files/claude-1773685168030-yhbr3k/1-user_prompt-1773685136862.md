Perform a store-ready localization and language quality audit for the entire app.

Goal:
Ensure the app is fully polished for public release, with consistent multilingual behavior, no broken translations, and clean first-launch language behavior suitable for web users and future app-store users.

Do NOT redesign the app and do NOT change business logic. Only audit, verify, and apply minimal localization fixes if necessary.

Please check all of the following:

1. First-launch language policy
- Confirm the app opens in English by default for all first-time users.
- Confirm this applies globally across the entire app.
- Confirm browser/device/OS locale is NOT overriding the first-launch language.
- Confirm the user's last manually selected language is restored on future visits.

2. Translation completeness
Audit all user-facing text in all supported languages and identify any:
- untranslated English leftovers in non-English modes
- mixed-language UI (e.g. half English / half translated)
- missing translation keys
- fallback strings showing raw keys or placeholders
- broken or inconsistent terminology across pages

3. Scope coverage
Check all major areas:
- Home page
- Resume / CV Builder
- Cover Letter Builder
- Templates
- FAQ
- Pricing / Upgrade / Pro sections
- Settings / language selector
- Modals
- Empty states
- Tooltips
- Buttons
- Form labels
- Helper text
- Validation messages
- Error messages
- Success messages
- Loading states
- AI generation UI
- Upgrade prompts
- Legal links and legal page labels

4. Consistency of terminology
Ensure important terms are translated consistently across the entire app, including:
- Resume / CV
- Cover Letter
- Professional Summary
- Skills
- Experience
- Education
- Templates
- Download / Export
- Upgrade / Pro / Premium
- Generate with AI
- Regenerate
- Rewrite
- Save
- Delete
- Language names in the language selector

5. Language selector quality
- Confirm all supported languages appear correctly in the selector
- Confirm language names are displayed properly
- Confirm switching languages updates the full app consistently
- Confirm no page remains in the old language after switching
- Confirm the selected language persists across refresh and revisit

6. No visual or UX issues caused by localization
Check for:
- text overflow
- clipped buttons
- wrapping issues
- layout breaks on mobile and desktop
- inconsistent spacing caused by longer translated strings
- truncated headings
- broken modals or cards in translated languages

7. Legal / store-facing readiness
Confirm that:
- Privacy Policy link label is correct in all languages
- Terms of Service link label is correct in all languages
- Legal links remain functional from the app UI
- No legal page entry point is missing or mislabeled in any language

8. Error and fallback quality
- Confirm all user-facing errors are clean and localized where intended
- No raw system errors should appear to users
- If a translation key is missing, ensure the app fails gracefully (prefer English fallback over broken keys)

9. No language flicker
- Confirm there is no flash of the wrong language on first launch
- Confirm there is no hydration mismatch or route-level language flicker during navigation

10. Minimal-change rule
- Do NOT change pricing, features, limits, app logic, or visual design
- Only make minimal fixes required to achieve clean, release-ready localization quality

Final report required:
- State whether the app is now localization-clean and release-ready
- List any issues found
- If fixes were made, list only the exact minimal localization changes made
- Explicitly confirm whether the app is suitable for:
  "First launch in English, multilingual use afterward, and public release readiness"
